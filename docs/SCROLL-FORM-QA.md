# 自动定位与桌面卡片返回验收

日期：2026-10-22。设备：HUAWEI Mate 80 Pro Max，API 26。

## 自动定位：已修复

- 原判底方法使用整个当日分区的高度，包含 44 vp 标题和 4 vp 间距，实际 List 视口更矮；末项仍被裁切时可能误判已经到底。现在读取 `list-today` 的实测高度并由 px 转 vp，未挂载时保留请求，布局后补做。
- 原调度只比较 `todayAnchorId`；取消完成后重新勾选同一项，下一项可能仍等于旧锚点，导致不触发。现在有效的首项完成操作独立发起定位。
- 旧延迟保存了旧索引。现在使用请求代次取消过期请求，执行前重新查找首个未完成项；关闭开关、切页、拖动或页面销毁不会执行过期请求。
- 保留末尾防跳：最后一条真实日程完整可见时不再多余滚动，不把末尾提示行算作必须定位的内容。

真机：缩小当日分区后，将首个未完成日程滚至顶部只剩约 20 px 的勾选热区，点击成功，完成数由 1/6 变为 2/6，下一项从 y=787 px 定位到 y=716 px，与正常首卡文字顶边一致。随后恢复本轮临时日程与设置；未删除任何已有日程。最终增加的布局就绪补做由自动回归覆盖，未再次修改真机任务状态复验。

## 卡片主题：同步加固，返回旧画面尚未消除

已保留的修改：

- 在 UIAbility 冷启动 `onCreate`、热启动 `onNewWant` 读取官方 `formInfo.FormParam.IDENTITY_KEY`，记录来源实例；来源卡片不在运行枚举结果中时也直接补齐并优先推送。
- 主应用多轮推送串行执行，每次固定数据快照，避免旧异步推送覆盖新配色；单张失效不阻断其它卡片。
- 移除卡片主题颜色的隐式过渡，避免不可见期间暂停、返回后续播颜色动画；勾号缩放、删除线透明度与未来条目淡出保留。

真机两轮：小卡 A + 中卡 B；从 A 的空白处打开应用，在设置改深色和海盐，再回桌面。B 已显示最终色时，A 在返回过程仍有短暂旧色画面，之后与 B 一致。第二轮使用官方 `reloadForms` 请求提供方重新取数，仍出现相同现象，因此已撤除这一无效尝试，不引入额外刷新开销。现象符合来源卡片返回缓存画面的表现，但没有证据将其判定为应用不可修复的平台缺陷；本次不把第二项标记为彻底修复。

已核对 SDK 的 FormKit 接口、CLI 官方文档《通过 router 或 call 事件刷新卡片内容》《卡片主动刷新》《卡片更新与数据交互》《ArkTS 卡片为组件添加动效》。没有引入未公开参数、额外权限、循环刷新或重新添加桌面卡片。
