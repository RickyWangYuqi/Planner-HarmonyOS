# 打卡交互优化验收

日期：2026-10-27。设备：HUAWEI Mate 80 Pro Max，API 26 Release，1320×2848。使用 npm 安装的 `@deveco/deveco-cli`，经 `scripts/deveco.ps1` 查阅本机文档、检查、构建和操作手机；没有将 Studio 自带 CLI 与 npm CLI 混用。

## 交互变更

1. 名称识别后的「点击开启自动递增」可点击，开关与提示同步更新；提示明确给出下一期完整名称。开关直接开启执行相同校验。无效数字、步长及溢出不启用。
2. 移除「生成下一期前确认」选项。开启即确认规则，后续周期自动接续；旧确认配置迁移为新语义。已有周期不重复生成，历史不改写，非法溢出仍保留人工调整入口。
3. 新手教程新增打卡管理与名称接续两项，升级为八项说明。旧版已读用户只展示一次新版。主页去掉长段操作说明，编辑器名称提示精简。
4. 详情 Scroll 顶部对齐，消除短内容默认居中造成的留白。统计卡周期数缩短为「共 X 期」并放于右上角；关闭复用日程编辑 IconButton。
5. 补卡改为独立二级组件，日历始终展开并显示每日状态。历史内容独立预填，选择过去有效未完成周期后确认补卡；完成后留在日历，支持连续补多个日期。返回复用 HistoryBackButton。
6. 今天 / 全部计划使用与主题模式相同的弹簧、跟手和轻微伸缩滑块；仅下方分节与卡片参与水平切换。编辑、补卡、完成和异常内容调整复用水平二级转场；系统返回先退回详情。
7. 卡片标题与状态放左侧，详情用右上角 44vp 箭头按钮，完成打卡是下方主题色主按钮。顶部标题与新建按钮使用与设置页相同的 HdsNavigation、可滚动绑定及渐变模糊设置。

## 按钮按压状态处理

日程编辑和打卡按钮原本有系统 Button 默认按压着色；部分图标还维护自己的按压状态。当前改为受控缩放反馈，点击执行业务之前同步清除状态，Touch Up / Cancel、离场同样清理。材质参数、系统分档、中性面板色、原生材质光效未修改。

核对 npm CLI 的 Button 文档确认 `stateEffect` 控制原生按压效果；共享按钮关闭该默认着色层，保留缩放及原生材质。官方 OpenHarmony ButtonPattern 的注入点击路径也会进入 pressed style，因此 CLI 注入点击与物理触摸并非完全相同。参考 [ButtonPattern 源码](https://raw.githubusercontent.com/openharmony/arkui_ace_engine/master/frameworks/core/components_ng/pattern/button/button_pattern.cpp)，不能据 master 源码单独断言手机 API 26 的物理触摸根因。

手机检查了打卡新建、识别提示、详情、编辑、补卡及日程编辑的打开 / 返回 / 关闭，稳定截图未见孤立按压灰层残留；回归测试额外覆盖无 Touch Up 的点击、取消、关闭和离场。没有宣称已完成大量物理触摸循环或 GPU 点光残留量测。
