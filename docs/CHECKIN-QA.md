# 打卡功能实现与手机验收记录

日期：2026-10-26 至 2026-10-27。工程：PlanerHarmony。验证设备：HUAWEI Mate 80 Pro Max，API 26 Release，1320×2848。

## 实现范围

- 底部增加独立「打卡」页，使用系统 checkmark_circle / checkmark_circle_fill 符号，沿用悬浮底栏与主题色。
- 多条计划、每日/周/月频率、范围平移或连续分段、生成前确认开关、备注、暂停/恢复/删除、补卡及撤销。
- 每个条目与周期日期唯一对应一条快照；确认前不覆盖范围。生成后的任务只进入当日日程，旧未完成任务沿用延期规则。
- 普通日程和桌面卡片共享 reducer，完成与进度同步到打卡。历史恢复保留周期；不能拖入未来分区。
- 已确认快照与计划配置分离，补卡不推进当前范围，频率历史和暂停区间参与统计。不存在的月日跳过。
- 时间线、单条和整体统计、空状态与简要引导、本地原子保存及失败重试。
- 删除计划清理未完成关联日程，已完成历史只读保留；普通历史列表的删除不清除独立打卡档案。

## 手机实际执行

1. 三个底栏页签、系统图标、打卡空状态与新建入口。
2. 创建「功能验证-背单词」，开始日期 2026-10-24，每天，初始 1–10，连续分段数量 10，生成前确认开启。
3. 今日产生单条打卡日程；完成后主页完成计数同步。从主页编辑图标跳到对应打卡详情。
4. 撤销完成的确认、补记 10-25、补卡标记、累计次数/完成率/连续值；重新安装启动后条目和记录保留。
5. 同一页面完成打卡，统计立即从 1 次/33% 更新为 2 次/67%，不用重启；暂停后列表和按钮立即更新，恢复需确认。
6. 真实跨至 10-27 后恢复计划，出现待确认的 11–20，10-26 仍保留已完成的 1–10。查看上一周期与推荐范围，暂不后再次打开仍待确认；起点大于终点时拒绝提交；手改为 12–20 后确认，仅新周期使用该范围。
7. 输入名称、日期和范围时，保存/确认按钮在键盘上方可见；下方日期输入框聚焦后只滚动弹层内容，原页面标题保持原位。
8. 删除测试条目先取消，再确认；停止后续生成并移除未完成日程，已完成历史按设计保留。未修改用户既有日程内容、主题或设置，未清空用户数据。

## 真机发现并修复的问题

- RESIZE_ONLY 会裁掉自定义材质容器内部的固定按钮。改为 NONE 配合窗口键盘高度和实际节点位置测量，仅对弹层内容施加局部避让；焦点跟随滚动，关闭时清理监听和定时器。
- 私有 Builder 接收计算后的统计对象/字符串会保留旧值。改为稳定 scope/条目 ID/周期 key，内部读取最新状态；通过数据 Watch 刷新统计和时间线。
- 新建计划的“下一期预览”曾显示初始范围。预览单独模拟本期已生成，展示 11–20；保存仍生成首期 1–10，并校验溢出。
