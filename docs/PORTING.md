# 序笺 · 桌面功能移植说明

本说明依据 `Planer` 的 README、AGENTS、design-qa、React 页面与组件、reducer、lib/data、store、Tauri 源码及业务测试整理。源码、资源、文档改动限定在 `PlanerHarmony`，未改动桌面 Planer 源码。更新日期：2026-10-16。

2026-10-20 品牌更新：鸿蒙端应用正式名称为「序笺」，系统显示名、应用内文案和新手教程已统一。文中的 `Planer` 仍指原桌面项目或既有技术标识；应用商店介绍见 [应用商店文案](STORE-LISTING.md)。

## 阅读结论与实现计划

桌面版为 Tauri 2 + React 18 + TypeScript + Vite，业务集中在纯 reducer 与日期 / 数据工具中；Rust 负责本地 JSON 文件和 Windows 窗口能力。没有服务端和账号，主界面、设置、历史三个页面共享一份状态。核心不是按独立日期查询数据库，而是修改 `currentDate` 时迁移当日、未来与历史列表。

实现方案保持原有 Stage 脚手架和 `entry` 模块，编译 / 目标版本为 26.0.0，最低兼容版本为 6.1.1(24)：ArkTS 类定义数据，纯函数处理动作，页面持有 `@State AppData`，每次变更产生新状态。使用应用私有文件保存完整 JSON，以自然保存列表排序和历史快照。主页与设置通过同一入口的原生底部 Tabs 切换，历史作为设置子页，保留独立滚动控制器；不引入大型状态、路由或数据库依赖。

视觉统一使用桌面四套明暗配色、矩形圆角和字号层次，图标使用官方 SVG 及 SDK 系统符号。手机保留双列表结构，使用安全区、弹性高度、触控目标及原生底部半模态表单；卡片只保留编辑按钮，排序与移动通过长按拖动完成。本轮在原生页签基础上增加设置 / 历史固定标题、主题模式弹簧滑块、拖动拾起与落位反馈，并调整删除与分组提交流程；保留 API 26 原生材质且加入最低 6.1.1(24) 的版本保护。验证分为纯业务回归、持久化故障模拟、ArkTS 检查、lint、HAP 构建和设备冒烟 / 触控验收。

## 数据模型

日期键统一使用本地时区 `YYYY-MM-DD`，时间戳使用 ISO 字符串。

| 类型 | 字段 |
| --- | --- |
| Task | `id`, `text`, `createdAt`, `group`, `startDate`, `dueDate`, `completed`, `completedAt`, `progress`, `plannedDate`, `archivedAt` |
| HistoryEntry | `date`（归档分组日期）, `tasks` |
| AppData | `version=1`, `currentDate`, `todayTasks`, `futureTasks`, `groups`, `history`, `settings`, `todayAnchorId` |
| Settings | `autoNumber`, `progressDefaultZero`, `autoScrollNextOnComplete`, `showGroups`, `todayPaneRatio`, `themeMode`, `colorPreset`；兼容保留 `alwaysOnTop`, `autoHideFullscreen`, `shrinkOnBlur`, `closeAction`, `launchAtStartup` |

`group/startDate/dueDate/completedAt/plannedDate/archivedAt` 可为 `null`；`progress` 为 0–100 的整数或 `null`。读取后归一为类实例并补默认值。已有空分组保留顺序，旧数据只从当日 / 未来任务补齐分组目录，不从历史补齐。

动作通过 `new AppAction(type)` 构造。`group/startDate/dueDate/progress` 为可选字段：`undefined` 表示保留，`null` 表示清除。`SET_SETTINGS` 提交完整 Settings；`REORDER` 使用 `from` 与 `toIndex`；`MOVE_TASK` 的 `to` 表示 `today/future`，`toIndex` 为移除源任务后的目标数组位置。`MOVE_GROUP.toIndex` 则是移除整组前的数组边界。

## 必须保留的业务规则

1. 未来任务新建按截止日期升序插入，后续手动排序不会被每次保存强行重新排序。编辑未来任务会重新按截止日插入，这与桌面一致。
2. 起始日期仅展示区间与日历标记；到期迁移以截止日期为准。未来任务移入当日后不显示或编辑隐藏区间。
3. 日期前进时，已完成当日任务按旧 `currentDate` 归档；未完成任务顺延；跨多日直接处理一次，期间到期未来任务追加到当日。
4. 日期回退不会撤销历史。仅把当日中隐藏截止日更晚的任务移回未来。
5. 设置进度 100 会置完成，低于 100 会取消完成；清除进度只清百分比。勾选完成不会覆盖原始 progress。
6. 未来“勾选完成”立即归档；在编辑表单把未来进度设为 100，桌面仍保留在未来列表，本实现保留这一边缘行为。
7. 恢复历史将完成状态、完成时间、归档信息清除，但保留原始进度。恢复到当日清除 dueDate，仍保留 startDate；恢复到未来优先使用选定日期或原 plannedDate。
8. 删除日程是永久删除，不进入历史。历史不是所有删除记录的回收站，仅保存已完成的归档日程。
9. 分组开启时保持每组唯一连续段；若组被拆散，按每组最右成员位置重新聚拢，组内相对顺序不变。关闭分组时不聚拢、不修改隐藏组归属。
10. 显式删除组不删任务。分区标题只处理当前区；表单标签删除立即依次处理两区。删除历史中的组名不会自动发生，恢复该历史日程会重新加入实际使用的组目录。
11. 只有完成当前第一个未完成的当日任务才更新下一项锚点。关闭自动定位清锚点，取消完成和普通编辑不触发滚动。

## 本轮界面架构与平台约束

- `Index.ets` 使用原生 `Tabs` / `BottomTabBarStyle`，主页与设置同级，历史从设置进入。索引采用 `index: $$this.activeTab`，`displayedTab` 在动画开始时同步图标，文字由原生选中颜色控制。`PlanerTabsModifier` 在 API 26 启用悬浮样式，旧系统使用普通底栏；内容保留底部安全间距。
- `SettingsView` 与 `HistoryView` 使用 `HdsNavigation` 的 MINI 固定标题、绑定 Scroller 及 `GRADIENT_BLUR` 滚动效果，标题不随内容消失。设置保持同级页面，无返回按钮；历史使用固定返回入口。窗口全屏布局且系统栏透明，`avoidLayoutSafeArea: true` 使标题主动避让系统栏，`enableComponentSafeArea: false` 使内容继续滚入标题及状态栏背后；Scroll 内部初始留白使用实际 safeTop + 标题高度（设置 56vp、历史另留 16vp），留白随内容滚走。MINI 标题在 `titleBar` 配置后指定。HDS 标题材质是 SDK 独立能力，不等同于把 API 26 `systemMaterial` 任意作用到普通卡片。
- `ThemeModePicker.ets` 保留三项固定文字与无障碍按钮，滑块前景通过裁切显示选中颜色。点击或水平拖动改变落点；跟随速度轻微拉伸，松手后弹簧回位；取消手势回到已保存模式。主题颜色仍采用 360 毫秒非线性缓动，位移 / 按压 / 展开采用弹簧曲线；物理弹簧不保证固定毫秒结束。
- 日程与分组拖动开启系统拾起阴影 / 圆角预览；源项淡出、目标槽随源卡片高度展开，单卡槽约束在 50–180 vp，避免长文本占位撑满分区、周围卡片避让。落点和数组索引转换后交给真实业务动作，取消或无效目标不移动；当日移到未来需确认日期后才提交。整组仅支持同区排序，不声称跨区整组移动。`dropGroup` 为 `@State`，使同一插入索引切换目标组时也能刷新预览归属。
- `TaskEditor` 的永久删除移到编辑页底部，宿主负责确认和保存；取消确认保留当前草稿。分组输入不再依赖先点击局部确认：主添加 / 保存采纳非空待确认名称，同名复用，空白名称保留已有选择；取消创建 / 整表、隐藏分组、移动模式与无效表单保持原语义。
- `Appearance.ets` 集中维护 Motion、Materials 与原生底栏兼容分支。API 26 的能力查询、材质构造、底栏属性和弹层选项均用直接 `deviceInfo.apiAvailable('26.0.0')` 保护，不能以返回 `undefined` 代替保护高版本调用。`module.json5` 的 `ohos.arkui.UIMaterial.state=enable` 作用于系统支持的组件；不支持的新能力回退到可读背景。
- 编辑、移动、日历的输入区、标签与按钮使用 `Materials.inset` 轻色叠层，不重复采样模糊。普通任务卡 / 设置卡保留轻毛玻璃。系统沉浸光感仍受设备和位置限制：不能宣称任意内容按钮都有真实系统沉浸材质。
- `PlanerIcon` 使用官方 SVG 和已核验系统符号；增强 SVG 解析在最低 6.1.1(24) 可用，颜色通过 `ColorMetrics` 转为 0–255 通道，交给 `drawing.ColorFilter.createBlendModeColorFilter(..., SRC_ATOP)`；这是官方 ResourceColor 重载使用的混色方式，最低兼容版本也可用，保留原始透明度及 mask 镂空。底栏 SVG 适配副本只调整根尺寸 / viewBox，原下载资源不变。
- `EntryAbility` 使用最低兼容版本可用的 `onSystemConfigurationUpdated` 订阅真实系统色，销毁时注销。全屏窗口中读取并监听系统栏、挖孔及导航指示器避让区，首页单独补顶部安全区，页签 / 历史承载层仅补底部安全区；原生半模态处理键盘可用高度。主机检查不能替代键盘、系统色切换或新标题的设备验收。

版本配置位于 `build-profile.json5`：`compileSdkVersion` / `targetSdkVersion` 均为 `26.0.0`，`compatibleSdkVersion` 为 `6.1.1(24)`，`app.products[].buildOption.strictMode.apiCompatibilityCheck` 为 `error`。版本写法依据本机 SDK 26 的 DevEco CLI 官方工程配置文档与 Hvigor schema；保留脚手架与签名字段。最低版本配置表示安装下限，仍需在 6.1.1(24) 设备验证降级界面。

## 本地保存与权限

存储位置为 `UIAbilityContext.filesDir/data.json`，与桌面 `%APPDATA%` 文件没有自动同步。保存按调用顺序排队，调用时固定 JSON 快照；临时文件写入、同步和读取校验完成后才替换主文件，并保留上一份备份。首次读取失败时不进入可编辑状态，防止覆盖原数据。

业务不需要公共文件访问、网络、通知或悬浮窗权限，因此不增加相关权限。继承脚手架的 EntryBackupAbility 配置，但没有新增用户可操作的导入导出功能。后台跨日依靠返回前台时检查，不申请长期后台任务。

## 2026-10-16：拾起绘制边界、连续边缘滚动与编辑避让

- List 视口向两侧各扩 16vp，再以等量内边距维持卡片原横坐标与宽度；`clipContent(ContentClipMode.BOUNDARY)` 将内边距纳入绘制范围，上下各预留 12vp。拾起放大与阴影可在留白内绘制，同时保留纵向列表边界。
- 源卡的 `shadow` 与 `dragPreviewOptions.modifier` 使用同一个 `liftShadow`，显式设置中性颜色、半径与偏移。预览不再启用默认阴影；静止卡片显式透明，避免 API 26 零半径阴影行为造成残留。原生与自定义拾起仍以系统 `onPreDrag` 阶段交接。
- 分组标签的选择态采用实心轻色与实线轮廓，新建入口为加号虚线按钮；删除态的叉号固定在右上角，标签本体以小角度往返弹簧动画提醒。关闭、提交、取消删除态和组件销毁时清理摇摆计时器。
- 页面与半模态均使用 NONE 键盘模式，避免全页缩放或重复避让。TaskEditor 通过主窗口 `keyboardHeightChange` 与初次 TYPE_KEYBOARD 区域读取，计算当前弹层底边同键盘顶部的交叠，只更新自身底部内边距；中间 Scroll 收缩、固定按钮抬起。根节点与输入框统一使用 `getPositionToWindowWithTransform()`，包含半模态位移；普通 Area/globalPosition 的 y 在真机为 0，不能用于此处的可见底边。关闭时注销相同回调，阻断迟到异步；布局变化后局部滚动聚焦的输入框。未改用户当前 `Materials.dialog`（REGULAR / #40）及普通 inset 的 #65 通透度。
