# Planer 日程便签 · HarmonyOS 手机端

基于桌面 Planer 1.1.0 实际业务代码与设计令牌实现的鸿蒙原生版本。保留当日 / 未来双列表、分组、进度、历史恢复和主题；使用 ArkTS、ArkUI、Stage 模型，编译与目标 SDK 为 26.0.0，最低兼容 HarmonyOS 6.1.1(24)。

工程沿用现有脚手架，模块为 `entry`，包名为 `com.example.planerharmony`。数据仅保存在应用沙箱，不连接业务服务器。

## 功能一览

### 日程

- 当日、未来日程的新增、编辑、永久删除；删除需确认。点击编辑按钮打开表单，点击日程正文不会误开编辑。卡片仅保留编辑按钮，永久删除位于编辑表单底部；原日程操作面板已移除。
- 未来日程使用起始 / 截止日期区间。起始可不填，默认为当前所选日期的下一天；两个日历在表单内显示，可滚动查看。填写正文后点击「添加」，若未选择截止日期会显示提示并平滑滚动到截止日期日历；键盘打开时先收起键盘再定位，选择有效日期后提示消失。
- 当日未完成日程跨日顺延，已完成日程跨日归档；未来日程截止日到期后进入当日。启动、回到前台及前台定时检查日期。
- 「选择日期」可切换真实今天及未来日期，未来起止日期打点提示。切换向前会执行日期滚动；回退时把隐藏截止日期更晚的当日任务放回未来。
- 勾选当日日程后显示删除线；勾选未来日程立即归档。编辑进度支持未设置及 0–100%，设为 100% 完成，低于 100% 取消完成。
- 长按识别成功时立即开始浮起；浮起、跟手和松手落位共用一套连续动画，不再等待系统后续拾起阶段或切换另一张预览。手指移动时卡片直接跟随，松手后平滑回到实际落点；原地长按后松手也自然回落。卡片与分组共用阴影与弹簧效果，经过目标位置时展开与卡片高度相配的落位槽，相邻卡片弹簧避让。松手后提交排序、跨列表或跨分组移动；无效落点和取消不改变数据。卡片排序与移动通过长按拖动完成，当日移至未来时先回落再打开日期确认，取消不移动日程。拖至列表上下边缘会连续自动滚动，靠近边缘时逐渐加速；停住手指仍可滚动，离开边缘、松手或到达列表尽头即停止。
- 未来移到当日时保留隐藏起止日期；再次移至未来时自动填入仍有效的原区间，允许调整。
- 当日 / 未来之间的分割条可拖动，分区比例自动保存。API 26 的未来列表延伸到屏幕底部，日程可从悬浮底栏后方滚过；末尾留白让最后一条仍能滑到页签上方操作，拖动自动滚动的触发区域位于底栏上方。
- 两区列表下方仍有未完整露出的日程时，底边仅用渐隐色提示；最后一条完整可见后自动淡出。未来区按悬浮底栏上方的可操作范围判断，拖动日程时暂时隐藏提示；提示不拦截触摸。

### 分组

- 设置中开启分组显示后，新建 / 编辑表单可选择分组或创建分组。再次点击已选分组可取消选择。
- 同名分组直接复用；尚未提交的新分组为表单草稿。填写组名后，可以先点「创建并选中」，也可以直接点日程的「添加 / 保存」，组名会与日程一并提交。空白名称不改变已有选择；取消创建或取消整张表单不保存新分组。
- 已保存的空分组继续保留，可在之后的日程中复用。历史中的分组不会在读取时复活已删除标签。
- 已有分组使用实心圆角标签，新建入口使用带加号的虚线轮廓按钮。长按分组标签进入删除状态，标签轻微摇摆，删除叉号位于右上角；点击标签退出删除态。删除已保存标签立即作用于当日与未来两区，即使取消表单也不撤回。组内日程保留并移到未分组末尾。
- 分组标题上的删除按钮只处理该分区；另一分区仍使用同名分组时保留目录。未分组不能删除。分组标题可整组拖动调整顺序；长按识别时，可见组员从各自位置缩拢为叠层圆角卡片，显示组名、数量及前两条摘要；松手后连续展开到实际落位位置，取消时展开回原组。收拢、跟手与展开沿用同一套弹簧动画。
- 关闭分组仅隐藏分组信息，保留任务所属分组与自由排序；重新开启会把同组任务聚拢，保持组内相对顺序。

### 历史日程

从「设置 → 历史日程」进入，按归档日期倒序展示。

- 原计划日等于当前所选日：恢复到当日。
- 原计划日在当前所选日之后：直接恢复到未来，保留原截止日期。
- 原计划日已过或缺失：选择恢复到当日或新的未来日期。
- 支持单条永久删除和清空全部历史，均需确认。

### 日程显示设置

| 设置 | 默认值 |
| --- | --- |
| 自动编号（两区各自从 1 开始） | 开 |
| 未设进度默认显示 0% | 关 |
| 完成后自动定位下一项 | 关 |
| 按分组显示日程 | 关 |
| 当日区域占比 | 45%，小屏按最小可用高度约束 |

自动定位仅在勾选完成当前第一个未完成的当日日程时推进；编辑、取消完成或普通增删不误触发定位。定位锚点随数据保存，关闭开关清空锚点。

### 外观与页面

| 设置 | 默认值 / 可选值 |
| --- | --- |
| 主题模式 | 跟随系统；可选浅色、深色 |
| 配色预设 | 海盐；可选森林、日落、墨影 |

主页与设置是底部页签中的两个同级页面；API 26 使用原生悬浮样式，6.1.1(24) 使用普通底栏。历史日程从设置进入，返回后仍停留在设置。设置与历史标题固定在状态栏下方，内容滚动时经过标题和透明状态栏背后的渐进模糊区，再滑出屏幕；设置首节与大标题间距收紧，保持与页面分节节奏一致；设置不显示返回按钮，历史保留返回入口。主页保留当日 / 未来上下分区，首个分组文字顶边与未开启分组时的首张日程卡片顶边对齐，两区保持相同的标题间距；自动保存失败时显示重试提示。

配色来自桌面八套明暗主题；布局使用 vp、文字使用 fp、采用系统字体，触控按钮约 44 vp。卡片、按钮及表单统一为矩形圆角；官方线形 / 实心 SVG 与系统符号覆盖全部图标，无须额外下载。主题模式支持点击或横向拖动选择，选中滑块跟随手势轻微伸缩并以弹簧回弹落位，文字位置固定。主题颜色以 360 毫秒非线性缓动切换，按压、展开与切页采用弹簧曲线，滚动列表在边界提供回弹。

API 26 原生底部 Tabs、半模态表单、确认弹窗和受支持系统组件使用平台沉浸材质；旧系统通过版本保护回退到普通底栏与可读弹层。编辑和日历中的输入区、标签、按钮只叠轻色，不再额外叠加模糊采样；普通任务卡与设置卡保留轻毛玻璃效果。沉浸材质受设备能力与组件位置限制，不代表每个按钮都具有系统沉浸光感。表单使用原生底部半模态，键盘弹出时只调整表单可用高度以保持操作按钮可见，透过材质看到的底层主页保持原位置与尺寸。页面采用全屏内容布局与透明系统栏，首页控件和滚动内容初始位置按实际顶部安全区避让，固定标题由系统导航组件避让；根背景延展至顶部状态栏与底部手势区，宽屏限制内容宽度。

本轮已在真机复验固定标题与滚动模糊、主题滑块、图标配色、分组直接保存、单卡排序 / 跨区移动和编辑删除；现场自然跨午夜也完成了未完成日程顺延。范围与最终截图见 [本轮交互验收记录](docs/INTERACTION-QA.md)。包含最后一次落点状态修订的检查、签名构建、安装和启动均通过；已执行范围与未覆盖场景分开记录。

### 窗口行为与功能边界

手机端不暴露 Windows 专属开关；保留数据字段以维持版本兼容，并在应用生命周期中处理前后台切换。

| 桌面能力 | 桌面默认值 | 手机端处理 |
| --- | --- | --- |
| 窗口置顶 | 关 | 不申请悬浮窗，不提供桌面置顶 |
| 任意应用全屏时隐藏 | 关 | 使用系统前后台调度 |
| 失焦缩小、鼠标悬浮展开 | 关 | 使用系统后台与任务切换 |
| 关闭时退出 / 托盘 | 退出程序 | 返回手势、系统任务管理，无托盘 |
| 开机启动 | 关 | 不申请后台启动能力 |
| 自由调整桌面窗口尺寸 | 最小 380×520 | 手机自适应及双列表比例调整 |

桌面实际代码未提供搜索 / 筛选、通知提醒、重复日程、导入导出、账号同步或业务网络接口，本工程也不新增这些功能。无须申请通知、网络或公共文件访问权限。

## 数据与架构

- `entry/src/main/ets/model/PlanerModel.ets`：强类型模型，包含任务、历史、设置、状态和动作；对象修改前深复制。
- `entry/src/main/ets/model/PlanerEngine.ets`：纯业务状态转换、日期滚动 / 回退、分组排序、历史恢复。
- `entry/src/main/ets/services/PlanerStorage.ets`：应用私有目录 `filesDir/data.json`；串行保存快照，临时文件写入、同步与校验后替换主文件，同时保留 `.bak`。读取失败保留文件并提供重试，禁止空数据覆盖。
- `entry/src/main/ets/pages/Index.ets`：页面状态与交互调度、主页 / 设置原生 Tabs、历史子页、半模态表单、日期检查及保存失败反馈。
- `entry/src/main/ets/components`：日程编辑、日历、设置、历史、可点击 / 拖动的 `ThemeModePicker`，列表与拖动浮层共用的 `TaskCardView`、组员收拢 / 展开的 `GroupDragVisual`，以及共享 `PlanerIcon` / `IconButton` 图标组件；设置与历史使用 HDS 固定标题及滚动渐变模糊。
- `entry/src/main/ets/theme/Theme.ets`：四套配色的浅 / 深色设计令牌。
- `entry/src/main/ets/theme/Appearance.ets`：统一 Motion 动画、受版本保护的 Materials、原生底栏兼容分支，以及表单轻色叠层。

完整数据字段、功能对齐矩阵和业务边缘说明见 [移植说明](docs/PORTING.md)。

## 开发

需要 Windows、Node.js ≥ 22、已安装的 DevEco CLI、支持 API 26 的 DevEco Studio / SDK，以及项目声明的 Hvigor / ohpm 依赖。本机工具链为 DevEco CLI 1.3.4、DevEco Studio 26.0.0.821、SDK 26.0.0.105。工程 `build-profile.json5` 明确设置 `compileSdkVersion: "26.0.0"`、`targetSdkVersion: "26.0.0"`、`compatibleSdkVersion: "6.1.1(24)"`；`app.products[].buildOption.strictMode.apiCompatibilityCheck` 为 `"error"`。API 26 专属调用与选项在直接版本判断内启用，最低版本设备尚待实际安装验证。

在 PowerShell 中进入项目目录。通过项目包装脚本调用 CLI，将日志与缓存放在项目 `.tooling`。初期 CLI 检查曾产生工具默认用户日志，后续通过包装脚本将 CLI 日志 / 缓存定向项目；未修改用户工具配置。

```powershell
Set-Location D:\2.Programming\PlanerHarmony

# 非本机安装路径时，显式指定 DevEco Studio 根目录
$env:DEVECO_CLI_STUDIO_PATH = 'D:\Software\DevEco Studio'

# 一轮修改完成后先检查，再构建
.\scripts\deveco.ps1 check arkts
.\scripts\deveco.ps1 check lint
.\scripts\deveco.ps1 build

# 业务、存储、编辑草稿与拖动落点回归
node scripts/test-engine.mjs
node scripts/test-storage.mjs
node scripts/test-editor.mjs
node scripts/test-drag.mjs

# DevEco Local Test（Hypium；无需设备，需完整构建工具链）
.\scripts\deveco.ps1 hvigor test -p module=entry -p coverage=false --no-daemon
```

`test-engine.mjs` 在内存中转换并运行实际 `.ets` 业务文件，`test-editor.mjs` 提取真实表单提交方法并调用业务引擎，均不修改应用数据。`test-drag.mjs` 提取真实拖动方法，验证落点到业务动作的转换、识别同步拾起、布局完成后落位与取消清理；编辑和拖动测试均不验证 ArkUI 渲染、真实手势或键盘。脚本自动寻找现有 TypeScript；在其它机器无法自动找到时，可设置 `$env:TYPESCRIPT_PATH` 为已安装 TypeScript 模块目录。

工程沿用脚手架。源码、资源、文档改动限定在 PlanerHarmony，未改动电脑端 Planer 源码。

## 运行与复现

用户已通过 DevEco Studio 配置签名。连接设备后使用以下命令构建、安装与启动。设备为 HUAWEI Mate 80 Pro Max（API 26 Release）。本轮已完成的真机流程见 [交互验收记录](docs/INTERACTION-QA.md)；最终修订已重新签名构建、安装并通过 `Smoke: PASS`。上一轮记录见 [界面验收记录](docs/VISUAL-QA.md)，更早业务流程见 [真机验收记录](docs/DEVICE-QA.md)。模拟器实例和本地镜像仍未配置。

```powershell
.\scripts\deveco.ps1 device list

# 已有模拟器时，名称以 list 实际输出为准
.\scripts\deveco.ps1 emulator start '实际模拟器名称'

```

基本复现流程：

1. 首次打开，新增两条当日日程和一条有起止日期的未来日程；编辑其中一条进度为 50%，查看编辑与日历的轻色叠层。
2. 进入设置并滚动，确认标题保持固定且背板渐变模糊；进入历史页检查固定标题与返回。点击、慢拖及快速拖动浅色 / 深色 / 跟随系统滑块，确认选中与实际主题一致。
3. 开启分组。新增或编辑时填写组名，直接点主「添加 / 保存」，确认任务归组且重启后保留；再检查同名复用、空白名称、取消创建与取消整表。
4. 长按卡片观察识别时立即浮起，先原地松手确认回落，再依次拖过前、中、末尾落点，检查空槽和相邻卡片避让；松手检查同一卡片连续落位及实际顺序。分别测试跨组、未来移至当日、当日移至未来后的日期确认，以及无效落点和取消。
5. 确认卡片仅保留编辑按钮，原操作面板入口已移除。进入编辑表单底部点击「删除日程」，验证取消确认保留草稿、确认删除后关闭表单。
6. 勾选当日日程并切换到下一天，检查归档与顺延；勾选未来日程检查立即归档，在历史页恢复、删除或清空。
7. 切换四套配色，调整分区比例后重启，确认数据与设置保留。6.1.1(24) 应使用普通底栏，API 26 使用悬浮底栏；最低版本安装与系统真实深浅切换需单独验收。
8. 长按分组标题，检查可见日程向摘要卡收拢；原地松手、取消或换位后检查展开到真实位置。缩小当日分区，拖动分组到上下边缘，检查连续滚动与实际排序；长按表单分组查看右上角叉号及摇摆。分别聚焦日程内容、新建分组输入框，检查键盘上方按钮可见且背景主页不动。未来表单输入正文但不选截止日期，点击「添加」检查提示和定位；滑动未来列表检查底部延展及最后一条的可操作性。超长列表、窄屏与大字体仍需扩展验证。
